PRODUCT
An LLM-agnostic, project-centric desktop app for coding, document management,
and process work. Unlike Claude Code or ChatGPT — where every conversation is
an isolated island and files get stranded inside the chat that produced them —
here the PROJECT is the durable container. Chats, documents, API keys, and
skills all belong to a project. Documents are a persistent, project-scoped
knowledge base the assistant retrieves from — never attachments stapled to one
chat. Everything is local-first (data lives on the user's machine).

PLATFORM & AESTHETIC
Native macOS desktop app (Electron, but must feel indistinguishable from a
native Swift/AppKit app).
- System font (SF Pro / -apple-system).
- Translucent window vibrancy; sidebars use macOS "sidebar" material.
- Inset traffic-light window controls; a slim draggable title bar.
- Full light AND dark mode (show both for the primary screens).
- Restrained palette: one blue accent (#0a84ff), neutral grays, subtle
  dividers, generous rounded corners, soft shadows. No heavy borders.

INFORMATION ARCHITECTURE — this is a MULTI-PAGE app with MODALS.
A persistent left sidebar (projects + chats) frames a main area that switches
between several full pages. A top-of-window segmented control or the sidebar
selects the active page for the current project:
  1) Chat (default)   2) Overview   3) Documents   4) Skills   5) Settings/Keys
Modals and popovers overlay any page.

PERSISTENT CHROME (on every page)
- Title bar: current project name (left); a "Model" dropdown on the right to
  switch the active LLM (Claude Opus, Claude Sonnet, GPT-4o, Local Llama) —
  model switching is a first-class, always-available feature.
- Left sidebar (~220px), two sections:
    • PROJECTS — selectable list + "+" (opens New Project modal).
    • CHATS — chats in the selected project; each row shows title + the model
      name as a subtitle; "+" starts a chat.
- A command palette (⌘K) overlay for jumping to any project, chat, document,
  or page, and running quick actions.

PAGE 1 — CHAT (default, three-column workspace)
- Left: the persistent sidebar (above).
- Center: the conversation. Message bubbles (user right-aligned, accent blue;
  assistant left-aligned, neutral gray). Auto-growing composer at the bottom
  with a Send button and hint "Ask anything… (⌘↩ to send)".
  IMPORTANT — in-chat SOURCES: assistant replies that used project documents
  show a small "Sources (n)" chip beneath the bubble. Clicking it opens a
  popover listing the retrieved documents with a relevance indicator and a
  short "why this was used" line; each item deep-links to open that document
  (Page 3). This makes retrieval visible.
- Right panel (~240px): DOCUMENTS for the current project — a compact list
  (title + source label), a "+" to add, and a hint that documents belong to the
  project so every chat can see them. Clicking a doc opens the Document reader.

PAGE 2 — PROJECT OVERVIEW / CONTINUITY
The "home base" that fixes the cold-start problem so a new chat inherits project
state. Include:
- Project header: name, description, key stats (chats, documents, last active).
- A "Project Index" summary card — an auto-maintained outline of what the
  project contains and its current state.
- A "Handoff / Recent activity" card — session-transition notes describing what
  happened recently, so a fresh chat has continuity.
- A "Tasks / Workflow" card — a lightweight task list with statuses
  (todo / in-progress / done).
- An "Inbox" drop zone — a dashed drag-and-drop area where new files land and
  get auto-related to this project (show an empty state and a "3 items to
  triage" state).

PAGE 3 — DOCUMENTS (library + reader)
- Master/detail: left, the project's document library (searchable/filterable
  list or grid with title, type, source, updated date); right, the DOCUMENT
  READER showing the rendered content (markdown/code/text), editable inline.
- The reader has a metadata rail: file type, source (chat/upload/user), created
  and updated, on-disk path, and a "Referenced by" list of the chats that
  created or reference this document (the chat↔document relationships), each
  deep-linking back to that chat.
- Empty state for a project with no documents yet.

PAGE 4 — SKILLS (per-project scoping)
- A list of available skills (name + description) each with an enable/disable
  toggle scoped to the CURRENT project — reinforce that skills from other
  projects are not in scope here. A "+" opens the New/Import Skill modal.
- Show the difference between a global skill and a project-authored one.

PAGE 5 — SETTINGS / KEY MANAGEMENT
- API keys section: list of stored keys (provider, label, scope = this project
  or Global, created date) with add/remove. Convey that keys are encrypted at
  rest (a lock/secure badge; the actual secret is never displayed — masked).
  "+" opens the Add API Key modal.
- General settings: default model, appearance (light/dark/system), data
  location.

MODALS & OVERLAYS TO DESIGN
- New Project (name + optional description).
- New / Import Document (title, drag-drop or paste content, choose type).
- Add API Key (provider dropdown, label, scope = project/global, secret field
  that's write-only/masked, with an "encrypted on your device" reassurance).
- New / Import Skill (name, description, definition, enable-for-this-project).
- Command Palette (⌘K) — search + action list.
- A destructive-action confirmation (e.g., delete/archive project).

STATES TO SHOW
- Empty first-run: no projects yet, inviting creation of the first project.
- Fully populated: several projects; a selected project with multiple chats; an
  active conversation showing a Sources chip + open Sources popover; a
  populated Documents reader; the Overview page with tasks and an inbox that
  has items to triage.
- Light and dark mode for the primary screens (Chat, Overview, Documents).
